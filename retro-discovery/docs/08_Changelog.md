# Entscheidungsprotokoll

## 2026-07

### HTML statt dynamischer UI

Entscheidung

Die Benutzeroberfläche wird überwiegend über HTML definiert.

Begründung

Bessere Wartbarkeit.

Einfachere Gestaltung.

Schnellere Entwicklung.

---

## 2026-07

### Einführung der Design Language

Entscheidung

Alle zukünftigen UI-Komponenten orientieren sich an einer zentralen Design Language.

Begründung

Konsistenz.

Einheitliches Erscheinungsbild.

Professioneller Entwicklungsprozess.

---

## 2026-07

### Produktorientierte Entwicklung

Entscheidung

Retro Discovery wird künftig wie ein eigenständiges Produkt entwickelt.

Nicht Feature-orientiert.

Sondern Vision → Design → Integration → Polish.

Begründung

Langfristige Wartbarkeit.

Konsistente Benutzererfahrung.

# Ein Vorschlag zur Versionsnummerierung

Da wir jetzt bewusst in eine professionelle Dokumentations- und Designphase eingestiegen sind, würde ich die bisherige Entwicklung als Version 0.x betrachten. Erst wenn die Discovery Station funktional und gestalterisch vollständig ist, würde ich den Meilenstein 1.0.0 setzen.

Das vermittelt auch nach außen den richtigen Eindruck:

0.4.x → Fundament und Dokumentation
0.5–0.9 → Ausbau der Funktionen und des Designs
1.0.0 → Erste vollständige öffentliche Version der Retro Discovery Station
